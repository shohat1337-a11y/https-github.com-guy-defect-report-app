# דוחות ליקויים – אפליקציית סיור באתרי בנייה

אפליקציית Web פשוטה ומותאמת למובייל לניהול והפקת דוחות ליקויים באתרי בנייה.
כל הממשק בעברית, כיוון כתיבה מלא מימין לשמאל (RTL), והדגש הוא על שימוש מהיר בטלפון תוך כדי הליכה באתר.

## מה האפליקציה עושה

- פתיחת דוח חדש עם פרטי הפרויקט.
- מעבר באתר, צילום תמונה לכל ליקוי ורישום התיאור והפתרון הנדרש.
- הוספת ליקויים ללא הגבלה, עריכה ומחיקה.
- הפקת דוח **PDF מקצועי בעברית וב-RTL** בסיום הסיור.

## טכנולוגיות

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS v4**
- **SQLite** דרך **Prisma ORM** (מסד נתונים מקומי, קובץ `prisma/dev.db`)
- **Puppeteer** להפקת PDF (רינדור דפדפן אמיתי → RTL ועברית תקינים)
- אחסון תמונות מקומי תחת `public/uploads/` (מבנה שמאפשר מעבר עתידי ל-Supabase Storage)

## התקנה והרצה

דרישה מוקדמת: Node.js 18+ (נבדק על Node 24).

```bash
# 1. התקנת התלויות
npm install

# 2. יצירת מסד הנתונים (מריץ את המיגרציות)
npx prisma migrate deploy

# 3. טעינת נתוני דוגמה (דוח אחד עם 3 ליקויים)
npm run db:seed

# 4. הרצת האפליקציה
npm run dev
```

האפליקציה תהיה זמינה בכתובת: **http://localhost:3000**

> הערה: הפקת ה-PDF משתמשת ב-Puppeteer, שמוריד גרסת Chromium בפעם הראשונה
> (מתבצע אוטומטית בזמן `npm install`).

## שימוש

1. **מסך ראשי** – רשימת כל הדוחות. כפתור גדול בתחתית: "פתיחת דוח חדש".
2. **דוח חדש** – ממלאים שם פרויקט, כותרת, תאריך ופרטים נוספים ולוחצים "שמור והתחל להוסיף ליקויים".
3. **מסך הדוח** – מציג את פרטי הדוח ואת רשימת הליקויים ככרטיסים. בתחתית: "הוספת ליקוי" ו-"סיום והפקת דוח PDF".
4. **הוספת ליקוי** – מצלמים/מעלים תמונה, ממלאים תיאור, פתרון, תחום עבודה, דחיפות, סטטוס וכו'.
   - "שמור והוסף ליקוי נוסף" – שומר ומנקה את הטופס להוספה מהירה.
   - "שמור וחזור לדוח" – שומר וחוזר למסך הדוח.
5. **עריכה/מחיקה** – כל דוח וכל ליקוי ניתנים לעריכה ולמחיקה (עם הודעת אישור).
6. **הפקת PDF** – מ-"סיום והפקת דוח PDF" או מכפתור "הפקת PDF" ברשימת הדוחות.

## איפה נשמרים הנתונים

- **מסד הנתונים:** קובץ SQLite מקומי ב-`prisma/dev.db`. הנתונים נשמרים בין ריצות ורענוני דפדפן.
- **תמונות:** בתיקייה `public/uploads/{מספר-דוח}/`. כל תמונה מקבלת שם ייחודי.
- מחיקת דוח מוחקת את הליקויים שלו (cascade) ואת קבצי התמונות שלהם.

## אחסון תמונות ב-Google Drive (אופציונלי)

כברירת מחדל התמונות נשמרות מקומית תחת `public/uploads/`. אפשר לחבר את האפליקציה
ל-**Google Drive** כך שכל תמונה חדשה תעלה ישירות לדרייב האישי (חיבור OAuth חד-פעמי).
כל עוד הדרייב לא מחובר, האפליקציה ממשיכה לעבוד עם אחסון מקומי — אין צורך בחיבור כדי להריץ.

**הגדרה (חד-פעמי):**

1. ב-[Google Cloud Console](https://console.cloud.google.com): צור פרויקט, הפעל **Google Drive API**,
   הגדר **OAuth consent screen** (External) והוסף את ה-Gmail שלך כ-Test user.
2. צור **OAuth client ID** מסוג **Web application** עם redirect URI:
   `http://localhost:3000/api/google/callback`.
3. הדבק את ה-Client ID וה-Secret אל `.env` (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`),
   הפעל מחדש את השרת, וגש ל-`http://localhost:3000/api/google/connect`.
4. אשר את הגישה; העמוד יציג `GOOGLE_REFRESH_TOKEN` — הדבק אותו אל `.env` והפעל מחדש.
5. אופציונלי: `GOOGLE_DRIVE_FOLDER_ID` כדי לשמור בתיקייה מסוימת בדרייב.

**איך זה עובד מבפנים:**
- Scope מצומצם `drive.file` — האפליקציה רואה רק קבצים שהיא עצמה יצרה, לא את כל הדרייב.
- תמונות דרייב נשמרות במסד כ-`/api/images/{fileId}` ומוגשות דרך צינור פנימי (`lib/google-drive.ts`),
  כך שהכרטיסים וה-PDF ממשיכים לעבוד דרך כתובות מאותו origin.
- תאימות אחורה: תמונות ישנות תחת `/uploads/` ממשיכות להיות מוצגות ונמחקות כרגיל.

## איך מפיקים PDF

- לחיצה על "סיום והפקת דוח PDF" במסך הדוח (מסמן את הדוח כ-"הושלם" ופותח את ה-PDF),
  או "הפקת PDF" ברשימת הדוחות.
- מאחורי הקלעים: מסלול `/api/reports/[id]/pdf` מפעיל Puppeteer, שמנווט לדף הדפסה פנימי
  (`/reports/[id]/print`) ומפיק PDF עם כותרת עליונה (שם פרויקט + מספר דוח), מספור עמודים,
  ומעבר עמוד תקין בין הליקויים. הקובץ נפתח בדפדפן וניתן להורדה לטלפון או למחשב.

## מבנה הפרויקט (עיקרי)

```
src/
  app/
    page.tsx                       מסך ראשי – רשימת דוחות
    reports/new/                   טופס דוח חדש
    reports/[id]/                  מסך דוח
    reports/[id]/edit/             עריכת פרטי דוח
    reports/[id]/print/            דף הדפסה נקי (ל-PDF)
    reports/[id]/defects/new/      הוספת ליקוי
    reports/[id]/defects/[defectId]/  עריכת ליקוי
    api/reports/...                מסלולי API (CRUD + PDF)
  components/                      רכיבי UI (כרטיסים, טפסים, Toast, דיאלוג אישור)
  lib/
    prisma.ts                      חיבור למסד הנתונים
    storage.ts                     שמירת/מחיקת תמונות (ניתן להחלפה ל-Supabase)
    pdf.ts                         הפקת PDF עם Puppeteer
    validation.ts, constants.ts, format.ts
prisma/
  schema.prisma                    סכימת מסד הנתונים (Report, Defect)
  seed.ts                          נתוני דוגמה
public/uploads/                    אחסון תמונות מקומי
```

## מגבלות הגרסה הראשונה (MVP)

- **ללא התחברות/משתמשים** – כל מי שיש לו גישה לשרת רואה את כל הדוחות.
- **מקומי בלבד** – מסד הנתונים והתמונות נשמרים על המחשב שמריץ את האפליקציה (לא בענן).
- **הפקת PDF דורשת Chromium** – Puppeteer מוריד אותו אוטומטית; בסביבת שרת מרוחקת ייתכן שיידרשו תלויות מערכת נוספות.
- אין ייצוא/גיבוי אוטומטי, אין חיפוש/סינון בדוחות, אין תרגום לשפות נוספות.

## שלושת השיפורים המומלצים לגרסה הבאה

1. **מעבר ל-Supabase (מסד נתונים + אחסון תמונות)** – כדי לגשת לדוחות מכמה מכשירים ולגבות את הנתונים בענן. שכבת `lib/storage.ts` כבר מופרדת בדיוק לשם כך.
2. **התחברות משתמשים והרשאות** – כניסה עם משתמש, כך שכל מפקח יראה את הדוחות שלו, עם הגנה על הנתונים.
3. **חיפוש, סינון ודחיסת תמונות** – סינון דוחות/ליקויים לפי סטטוס/דחיפות/תחום, ודחיסת התמונות אוטומטית בעת ההעלאה כדי להקטין נפח ולהאיץ את הפקת ה-PDF.
